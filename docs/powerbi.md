# Power BI report: model, measures and checks

Project: [`powerbi/OlistDashboard.pbip`](../powerbi/OlistDashboard.pbip) (PBIP format: TMDL semantic model +
PBIR report, all text files). Generated by [`src/build_powerbi_project.py`](../src/build_powerbi_project.py) from the
Parquet files written by `src/export_powerbi.py`.

## Model

Star schema with one order-level fact. Only complete months (2017-01 to 2018-08) are loaded.

| Table | Grain | Rows loaded | Role |
|---|---|---|---|
| fct_orders | one order | orders in complete months | Main fact: values, delivery, review, repeat flags |
| fct_order_items | one item | items of those orders | Category and seller analysis |
| dim_date | one day | 608 | Date table (marked), month axis |
| dim_customer | one person (`customer_unique_id`) | cohorts 2017-01..2018-08 | Repeat-customer share |
| cohort_retention | one cohort | 20 | Pre-computed in SQL (`sql/metrics/08`), keeps the observation-window logic |
| Measures | — | — | All DAX measures |

Relationships (all many-to-one, single direction):

```
dim_date[date]                      1 ──< fct_orders[purchase_date]
fct_orders[order_id]                1 ──< fct_order_items[order_id]
dim_customer[customer_unique_id]    1 ──< fct_orders[customer_unique_id]
```

A date filter reaches the items through `fct_orders`, and `fct_orders` is unique per order, so the
order → item relationship cannot double count.

## Measures (DAX)

All measures are in [`Measures.tmdl`](../powerbi/OlistDashboard.SemanticModel/definition/tables/Measures.tmdl). The key ones:

```dax
Valid Orders  = CALCULATE(COUNTROWS(fct_orders), fct_orders[is_valid] = TRUE())
Product Value = CALCULATE(SUM(fct_orders[product_value]), fct_orders[is_valid] = TRUE())

AOV =
DIVIDE(
    [Product Value],
    CALCULATE(COUNTROWS(fct_orders), fct_orders[is_valid] = TRUE(), fct_orders[n_items] > 0)
)

Product Value MoM % =
VAR CurrentValue  = [Product Value]
VAR PreviousValue = CALCULATE([Product Value], DATEADD(dim_date[date], -1, MONTH))
RETURN
    IF(NOT ISBLANK(PreviousValue), DIVIDE(CurrentValue - PreviousValue, PreviousValue))

Late Rate = DIVIDE([Late Orders], [Delivered Orders])

Returning Order Share =
DIVIDE(CALCULATE(COUNTROWS(fct_orders), fct_orders[is_return_order] = TRUE()), [Valid Orders])

Category Share =
DIVIDE([Item Product Value], CALCULATE([Item Product Value], ALL(fct_order_items[category])))
```

Why `DIVIDE` and not `/`: it returns blank instead of an error when the denominator is 0 (e.g. a state with no
delivered orders in a month).

Why `CALCULATE(..., ALL(fct_order_items[category]))`: it removes the category filter from the denominator only,
so each category's value is divided by the total for the current filters (month, state).
